# 结构变化下的跨智能体复用（C1 补证，2026-11-09 起）

## 起因

论文 C1 写的是“不同智能体的查询带着不同的过滤、聚合与分析目标，却依赖同一份计算”，要求提取出的定义能跨这些变化复用。
现有证据只覆盖时间变化：TPC-DS 群体评测（`exp/2026-10-12-population`）每个指标的计分题都只换期间（单月、跨期差值、
最高月、环比增幅最大月、高于均值的月数），十一种更新与 diverse scenarios 也一样。这时把学习会话的 SQL 换个月份就够用，
示例检索（Table IV：9.3k token、100%）与 MAVRA（10.0k、98%）持平；而 MAVRA 的 `run_metric` 也只接受时间参数，
论文 §IV 写的也只是“把期间提成参数”。用户 11-09 选定：增强方法并补跑一个真正考结构变化的群体评测，
对照无记忆、示例检索与 TeCoD（需要充值）。

这不是换一个“对我们有利”的负载：题型按 C1 的原话设计，设计写在看到任何结果之前；Table IV / Fig. 8 保持不变，
照实写明只变时间时直接共享 SQL 就够了；正式运行只跑一轮设计，无论结果都报告。MAVRA 若不占优，就收窄 C1 的文字，
不再改方法或题目重跑。

## 方法增强（写于看到任何结果之前）

`run_metric` 新增三种按维度属性（`表.列`）的问法，由结构化定义编译执行（`src/metric.rs` `compile_with`，
`src/middle/metrics.rs` `slice_join`）：

- `slice`：期间内属性等于某值的部分；`slice_diff`：两个属性值之差；`rank_by`：期间内取值最高的属性值
  （不计属性为空的行，并列取最小者）。
- 属性所在的表已在定义中（事实表、定义的关联或日期维度）时不需要新关联；否则从共享的关联经验中取事实表到该表的路径
  （当前版本上验证过的直接复用；没有时用 `join_path` 的探索与验证得出并存入，所有智能体与定义共用），只接受事实表为多侧、
  维度键唯一的多对一路径，切片或分组不放大事实行；找不到时拒绝并说明原因，智能体自行计算。
- 定义原有的关联、口径过滤、粒度与时间归属不变；非维度问法编译出的 SQL 与原编译器逐字相同（单元测试）。
- MAVRA 的工具说明与使用提示各加一句维度问法（属于 MAVRA 方法本身；其他组的提示不变）。

## 负载：题集 v3（`metric-bench --question-set v3`）

TPC-DS SF1，与 Section V-C 同样的 5 个指标（`tpcds-defs.json`，定义与学习题不变）。每个指标 7 道题：

| 题号 | 类别 | 题目（留出年 2002，学习年 2001） |
|---|---|---|
| L1、L2 | 学习（给出口径） | 2001 年 3 月、2000 年 11 月的值（同 v2） |
| P1 | 对照：只变时间 | 2002 年 9 月的值 |
| T1 | 维度过滤 | 2002 年 9 月，商品类别（item.i_category）为某类别的值；类别按 M1–M5 依次取 Music、Shoes、Electronics、Home、Sports |
| T2 | 维度之差 | 2002 年，门店所在城市（store.s_city）为 Midway 的值减 Fairview 的值 |
| T3 | 按维度排名 | 2002 年取值最高的商品类别 |
| T4 | 按维度排名 | 2002 年取值最高的星期（date_dim.d_day_name） |

计分题只给指标名，不给口径；维度在题面中写明列名（对所有组相同）。维度的选择：TPC-DS 的门店有多个版本
（同一门店编号 6 个、店名不唯一），按门店分组有歧义，因此只用没有歧义的商品类别、门店城市与星期。需要新关联的题：
M1 的 T2；M3、M4 的 T1、T3；M5 的 T1、T2、T3（其余维度已在定义中，星期在日期维度上）。

判题：维度题的标准答案由手写的判题基础计算（`tpcds-defs.json` 的 `judge` 与 `judge_dims`：按业务定义手写的度量、
FROM、口径过滤与事实表到维度表的关联条件，加模式描述的区分列过滤），不用定义库里的结构化定义，也不经过
`metric::compile`。开跑前（不调用模型）核对手写判题基础与参照定义在学习年 3 月、留出年 9 月的单月值一致
（`--bank-probe`，`v3-gold-check.json`）。2026-11-09 核对结果：10 个单月值全部一致；20 道维度题都有答案，
排名题前两名的相对差距 0.30%–46%（最小：M4-T4 Friday/Thursday 0.30%，M5-T3 Music/Electronics 0.37%，
M2-T3 Music/Electronics 0.43%）。
看过这些差距后没有改动任何题目或取值。

## 设计（写于看到任何结果之前）

- 群体评测同 Section V-C：16 个智能体依次到来（同时在场 1 个），每个智能体从 35 道题中不放回抽 7 道、顺序随机；
  第 r 轮用种子 r，各组抽到的题相同（配对）。学习题给出口径，其余只给指标名；记忆从空开始，只从给出口径且答对的
  学习会话学习。不施加数据更新（`--returning 0`）：本实验只考结构变化下的复用，维护已由其他实验覆盖。
- 四组：
  - 无记忆（`middle-alone`）：同样的中间层工具（含 `join_path`），没有跨题状态；
  - 示例检索（`traj-global`）：共享答对的学习会话（题面、SQL 与算式），按题面检索；
  - TeCoD（`paper-tecod`，SIGMOD 2026）：每格一个共享模板池，选择、提示与入池 SQL 同变更实验的 TeCoD 组
    （`tools/relbench/tecod_server.py`），按群体评测的规则改两处（`tecod-service.py`）：不给对错反馈；只从给出口径且
    答对的学习题入池；被遮蔽的题面另遮蔽「」中的维度取值。选择耗时不计入作答时间（同变更实验）；
  - MAVRA（`metric-global-snap`，同 Section V-C）：本次增强后的 `run_metric`。
- 模型：DeepSeek 官方 API `deepseek-flash`，智能体与提炼器都开思考、推理强度 high（同 Section V-C 的设置），
  20 轮，120 秒 SQL 超时，每题最多查找 3 次记忆。
- 5 轮（r1–r5，同 Section V-C 的 5 次配对重复；11-09 冒烟返回任何答案之前由 3 轮改为 5 轮，以减小轮间噪声）。
  代码与二进制在开跑前提交并记录 sha256；冒烟只检查功能，结果不用，冒烟中的正确率不用于任何设计决定；
  冒烟中发现的 MAVRA 机制故障（工具调用、关联解析、拒绝）按日志修复后重新冒烟，修复记入下文。
- 正式结果出来后不改题目、维度或取值；若 MAVRA 不占优，只允许改进方法本身，作为新版本与各组配对补跑，新旧版本都报告。

## 分析方案（写于看到任何结果之前）

1. 每题代价：token = 会话的输入 + 输出 token，触发学习时加提炼的 token；时间 = 会话第一次调用到最终答案的秒数。
2. 主要指标（5 轮合并，并给出每轮的值与范围）：维度题（T1–T4）的正确率、每题 token 与时间；对照题（P1）的同样指标；
   每轮 112 个会话的累计 token 与时间。
3. 预先声明的比较：MAVRA 与示例检索、TeCoD 在维度题正确率与每题 token 上的差别；MAVRA 与无记忆在累计 token 与时间上的差别。
4. 次要：按题型（T1–T4）与“是否需要新关联”分开的正确率；MAVRA 维度题中经 `run_metric` 维度问法作答的比例、
   新关联来自复用还是探索、被拒绝的次数。
5. 服务端失败不计分、不计代价（同 Section V-C）；不删除任何组或轮次。论文中 Table IV / Fig. 8 不变，本实验作为新增结果写入；
   结果不利时照实写并收窄 C1。
